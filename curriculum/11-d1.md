# 11. D1

- 前提: 08
- 必要なもの: 無料プランで可（上限は Limits ページを確認）
- 成果物の置き場所: `labs/11-d1/`

## ゴール

- D1 のデータベースを作り、マイグレーションでスキーマを管理できる
- Worker から prepared statement で安全にクエリできる
- バックアップと復元（Time Travel）を体験する

## 演習

### 11-1 `[CLI]` データベースとマイグレーション

`wrangler d1 create` でデータベースを作り、`wrangler d1 migrations create` / `apply` で `users` と `posts` テーブルを作る。ローカル（`--local`）とリモート（`--remote`）の両方に適用する。

**完了条件:** `wrangler d1 execute --remote --command "SELECT ..."` でテーブルを確認できる。

### 11-2 `[Code]` CRUD API

`posts` の CRUD API を作る。

- 必ず `prepare().bind()` を使う
- 一覧はページネーションする
- 複数の書き込みは `batch()` で行う

**完了条件:** SQL インジェクションを試みる入力（`' OR 1=1 --` など）が無害であることを確認する。

### 11-3 `[Code]` テスト

08 で学んだ vitest 環境で、テスト前にマイグレーションを適用し、API の結合テストを書く。

### 11-4 `[CLI]` 壊して戻す

わざとテーブルのデータを消し、Time Travel で消す前の時点に復元する。

**完了条件:** 復元の手順と、どの時点まで戻れるかを説明できる。

### 11-5 `[IaC]` D1 を Terraform で作る

D1 データベース自体は Terraform、スキーマはマイグレーション（wrangler）で管理する構成にする。

**完了条件:** 「DB の作成」と「スキーマ変更」をそれぞれどのツールで、どの順番で行うかを `labs/11-d1/DECISION.md` に書く。

## チェックポイント

- D1 はどこにデータを持っているか？ 遠い地域からのクエリのレイテンシはどうなる？
- 1 つの巨大な D1 データベースより、テナントごとに分けた多数の D1 が推奨されうるのはなぜか？
- マイグレーションを本番に適用するタイミングと、Worker のデプロイの順番はどうするべきか？

## 発展課題

- Drizzle ORM などを導入し、型安全なクエリにする。
- Read replication と Sessions API を試し、読み取りの一貫性について考える。
