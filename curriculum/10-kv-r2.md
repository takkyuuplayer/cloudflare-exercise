# 10. KV と R2

- 前提: 08
- 必要なもの: KV は無料プランで可。**R2 は利用開始時に支払い方法の登録が必要な場合がある**（料金ページを先に確認する）
- 成果物の置き場所: `labs/10-kv-r2/`

## ゴール

- KV の結果整合性と、それが向く / 向かないユースケースを説明できる
- R2 にオブジェクトを保存・取得でき、S3 互換 API からも操作できる
- ストレージリソースを Terraform で作り、Worker からバインディングで使える

## 演習

### 10-1 `[Code]` 短縮 URL サービス（KV）

- `POST /shorten`（URL を受け取り、短いキーを発行して KV に保存）
- `GET /:key`（302 リダイレクト）
- 有効期限付きのリンク（`expirationTtl`）

**完了条件:** 作った短縮 URL がブラウザでリダイレクトする。期限切れのリンクが 404 になる。

### 10-2 `[CLI]` 結果整合性を観察する

値を更新した直後に、別の地域（VPN など、なければ `wrangler dev --remote` と本番）から読むとどうなるかを試す。ドキュメントの「伝播にかかる時間」の記述と照らし合わせる。

**完了条件:** 「KV をカウンターに使ってはいけない」理由を説明できる。

### 10-3 `[Code]` 画像アップローダー（R2）

- `PUT /images/:name` で R2 に保存（`Content-Type` も保存）
- `GET /images/:name` で取得（`ETag` と条件付きリクエストに対応できるとなお良い）
- `GET /images` で一覧

**完了条件:** ブラウザで画像が表示される。

### 10-4 `[CLI]` S3 互換 API

R2 の API トークン（S3 互換の Access Key）を作り、`aws s3` CLI や `rclone` で同じバケットを操作する。

**完了条件:** CLI でアップロードしたファイルが 10-3 の Worker から取得できる。

### 10-5 `[IaC]` ストレージを Terraform で管理する

KV namespace と R2 バケット（必要ならライフサイクルルール、CORS 設定も）を Terraform で作り直し、Worker のバインディングを差し替える。

**完了条件:** `terraform plan` が差分なしで、Worker が新しいリソースで動く。

## チェックポイント

- KV・R2・D1・Durable Objects のどれを使うべきか、次のデータで答える: セッション、ユーザーのアップロード動画、注文データ、チャットルームの状態
- R2 にエグレス料金がないことはどんな設計判断に影響するか？
- R2 のパブリックバケット（`r2.dev` / カスタムドメイン）と Worker 経由の配信はどう使い分ける？

## 発展課題

- 署名付き URL（presigned URL）でクライアントから R2 に直接アップロードさせる。
- R2 のカスタムドメインを設定し、05 で学んだキャッシュと組み合わせる。

## 後片付け

- R2 のオブジェクトを削除してからバケットを削除する（Terraform で管理していれば `destroy`）。
