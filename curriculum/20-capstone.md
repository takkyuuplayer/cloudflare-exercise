# 20. 卒業制作

- 前提: Part 1〜3、19（Part 2, 4 は扱った範囲で）
- 成果物の置き場所: `labs/20-capstone/`, `infra/`

## ゴール

- 要件から Cloudflare の製品を選び、構成を設計できる
- **リポジトリから全体を再現できる**サービスを作る

## 要件

題材は自由。思いつかなければ次のどれか。

- 学習ノート共有サービス（Access で認証 / D1 にノート / R2 に画像 / AI で要約）
- 小さなイベント受付サイト（Static Assets / Turnstile / D1 / Queues でメール送信）
- 社内向けリンク集 + 短縮 URL（Access / KV / Analytics Engine でクリック計測）

必須条件:

1. **構成図と設計判断** — `labs/20-capstone/DESIGN.md` に、使う製品と選んだ理由、使わなかった選択肢を書く
2. **IaC で再現できる** — Cloudflare 側のリソースはすべて Terraform か wrangler の設定から作られている。Dashboard での手作業は手順書に残っているものだけ
3. **テストと CI/CD** — 19 の仕組みでテスト・デプロイされる
4. **セキュリティ** — 認証・入力検証・最小権限のトークン・シークレット管理
5. **観測できる** — 障害時に何を見ればよいかが `DESIGN.md` に書いてある
6. **後片付けできる** — すべてのリソースを削除する手順がある

## 進め方

1. `DESIGN.md` を書き、コーチとレビューする（設計レビュー）
2. 小さく作ってデプロイし、少しずつ機能を足す
3. 完成したら、**別のアカウント（または全リソースを削除した状態）から README の手順だけで再構築**できるか試す
4. コーチと振り返りをする: 学んだこと、まだ自信がない分野、次に学ぶこと

## 評価の観点（コーチ用）

- 製品の選択に根拠があるか（「なんとなく KV」になっていないか）
- エッジで処理すべきもの・オリジン / ストレージに任せるべきものの切り分け
- ドリフトがないか（`terraform plan` が差分なし）
- 料金と上限を意識しているか
